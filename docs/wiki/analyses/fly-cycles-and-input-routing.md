# Fly cycles and input routing audit

The current four-update choice covers short sensory-to-motor paths, while directed disconnections and the all-neuron readout limit what graph reachability alone can establish.

Last updated: 2026-09-19

Related: [Connectome actor](../concepts/connectome-actor.md), [Fixed reservoir](../concepts/fixed-reservoir-controller.md), [System audit](system-audit-2026-09-15.md), [Experiment workflow](../workflows/connectome-experiments.md)

## Scope and update rule

The matched asymmetric fly case in `configs/connectome/suites/ppo_lstm323_fly1952_asymmetric_noaux_mlp128x32x32_rollout_kl_100b.yaml` selects the 1,952-cell graph, learned `128/32/32` interface MLPs, all-neuron action readout, and `dynamics.neural_updates: 4`. Its saved `resolved_config.yaml` in the ignored training directory verifies those settings, the 140-value observation partition and actor input normalization; the suite process and fly child were running when checked. Other historical profiles use a 144-value structured interface, motor-only readout, or a fixed input encoder; their timing and routing should not be conflated with the current matched case.

`connectome_network_builder.py` computes both input adapters once per robot decision and holds their drives fixed for `K` synchronous updates. Each update reads the old hidden vector through `W[target, source]`, adds sensory/descending drive to the receiving population, then applies leak and `tanh`. A new external signal reaches an input-port cell on update 1 and a neuron `L` graph edges downstream on update `L+1`. The state persists between robot decisions and resets at episode boundaries. For `K>1`, the substep leak is `1-(1-leak)^(1/K)`, preserving passive decay over one decision; it does not make different `K` dynamically equivalent. The action head reads the state after the final update. All-neuron readout can therefore use directly driven input-port activity at `K=1`, although that route does not require the recurrent graph to process the input.

## Directed reachability in the pinned compact graph

Recomputed from `data/connectomes/processed/malecns_1952/biological.npz` on 2026-09-19, using only nonzero `values` and the stored postsynaptic-row/presynaptic-column convention. The file has 1,952 neurons, 33,720 nonzero directed pairs, 384 sensory ports, 157 descending ports and 135 motor readout cells. Distances are minimum directed edge counts from **any** member of the named source set; they do not mean each individual input cell can reach each target. `K=L+1` refers to fresh externally injected data, not propagation of an already active source state.

| Source set | Motor cells at edge distance 1 / 2 / 3 | Motor cells unreachable | Minimum K to reach each reachable motor from at least one source |
| --- | ---: | ---: | ---: |
| All 384 sensory ports | 53 / 70 / 7 | 5 | 4 |
| All 157 descending ports | 76 / 54 / 0 | 5 | 3 |
| Union of all 541 input ports | 85 / 45 / 0 | 5 | 3 |
| Fixed encoder's 87 driven proprioceptor ports | 53 / 68 / 9 | 5 | 4 |
| Fixed encoder's 24 goal-driven descending ports | 17 / 88 / 25 | 5 | 4 |

From the union of all 541 input ports, 27 neurons are unreachable, 19 are four-update recipients at distance 3, and two reachable neurons need distance 4 and thus `K=5` for fresh input. Graph-wide pairwise communication is impossible for any finite `K`: there are 445 strongly connected components and 44 isolated vertices; the largest strongly connected component contains 1,491 cells and has directed diameter 10. Even individual input-to-motor pairs are not universally reachable: 7,373 of 73,035 pairs have no directed route, and the longest reachable pair has nine edges, requiring `K=10` for its fresh injected input to reach that motor within one decision. Four updates are therefore a population-level motor coverage threshold, not an all-to-all threshold.

The five motors unreachable from any direct input remain disconnected from **new input** via the filtered recurrent graph. The reachability calculation is a structural upper bound on possible influence, not evidence of useful signal: learned weights, leak, path attenuation, cancellation and tanh saturation can make a short route ineffective. Repeated updates can improve temporal filtering or recurrent mixing, but can also suppress input sensitivity, settle into an unhelpful state, and increase rollout compute and BPTT depth. State carried across control decisions lets a ten-edge recurrent influence in the largest strongly connected component unfold over later decisions even at `K=4`; it does not make that influence available in the same action decision.

## What the current inputs actually do

The 140-value learned-adapter profile routes observation slices `[0,125)` and `[137,140)` (128 values) through a bias-free MLP into **all 384** selected sensory ports. These values include joint position/velocity, previous joint targets, palm/object pose, fingertip and object-keypoint positions relative to the palm, and object scale. The 12 object-keypoint goal errors `[125,137)` plus a learned 32-value **SAPG member** embedding go through a second bias-free MLP into all 157 descending ports. The scalar member ID selects an embedding row and a conditioned Gaussian log-scale row; it is an optimizer/exploration identity, not a biological goal. The actor observation is normalized per coordinate before the learned adapters, but the adapters' final outputs are unbounded.

This preserves the SimToolReal policy information and provides learned cross-species interfaces, but the sensory adapter mixes task context and prior commands into proprioceptive **and tactile** fly cells without sensor-type semantics. The task observation supplies no measured tactile signal, and the compact graph has no visual input population for object-pose estimates. Goal/context through descending cells is a reasonable command-interface hypothesis, but dense projection to every descending cell does not respect command channels or anatomy. The current all-neuron action readout can directly use sensory and descending states, bypassing a motor-path bottleneck. These are engineering choices, not verified biological mappings or a demonstrated optimum. In earlier 1,952-cell checkpoints, the [system audit](system-audit-2026-09-15.md#finding-3-the-tanh-circuits-input-neurons-are-nearly-saturated) found substantial sensory/descending preactivation saturation; that measurement does not establish the operating point of the current matched run.

The existing 144-value structured profile is a separate alternative: joint and fingertip proprioceptive information is grouped by arm/finger and routed only to 92 selected proprioceptor cells; 30 context values, 12 goal errors and the 32-value SAPG embedding are routed to descending cells. It deliberately leaves tactile cells without fabricated touch data. The fixed-reservoir profile uses YAML-owned bounded population codes, routes goal/context into selected descending cells, and conditions the **readout**, rather than the recurrent circuit, on the SAPG embedding. Its 87 driven proprioceptors and 24 goal-driven descending cells explain the fixed-encoder `K=4` population coverage result above. Fixed per-channel calibration still needs validation; its existing family scales were unequal in a saved observation snapshot.

## Decision and testable alternatives

For the current **all-neuron-readout** actor, `K=4` is a reasonable experimental setting, not a known minimum. `K=1` already allows fresh observations and goal to affect the current action through directly driven cells; `K=3` covers the union's reachable motors through at least one direct input port; `K=4` covers every reachable motor from at least one sensory port. More than four can alter the computation and may help, but graph coverage alone does not justify it. For a motor-only actor that must receive fresh input from the sensory population in the same decision, four is the minimum under this graph and update order. No finite value makes every cell communicate with every other cell.

Prioritize a matched `K={1,2,3,4,8}` experiment with fresh training for each `K`, same graph, input map, readout, seeds and environment-frame budget, and separate throughput/wall-time reporting. Probe current-observation and goal perturbation responses at the action and motor-state outputs, feature variance/rank, input-drive and tanh-saturation distributions, and closed-loop task success. A checkpoint-only `K` sweep can diagnose sensitivity but is not a performance comparison between trained architectures. Include a motor-only or directly-driven-cell-excluded readout control when asking whether extra graph processing helps; the all-neuron head offers a short path at every `K`.

For routing, compare the current dense learned map with the existing structured body-to-proprioceptor/context-to-descending map, controlling for task observation representation, readout and parameter budget. A more targeted candidate would send joint position/velocity and real contact/load estimates (only if available to the deployed actor) to corresponding sensory classes, previous targets and high-level goal commands to descending cells, and SAPG identity to the action readout or only to the policy distribution. The SAPG relocation is implemented for the fixed reservoir but requires a new YAML-selectable option for learned-adapter profiles. A separate modular option lets a higher-level task policy send low-dimensional descending commands while the fly circuit handles local feedback; the robot-action readout can learn a bounded residual. A full-CNS visual variant could route actual camera data into optic input populations, but that changes the graph and sensor contract. Calibrate or bound input drive before assuming more cycles will recover saturated responses. None of these alternatives is established as the best by the present graph audit.
